## 一、Bug：无法语音输入

### 1.1 根因

v1.1 的语音追问用的是 Chrome 自带的 `webkitSpeechRecognition`。它**不在本机识别**，而是把音频发到 Google 的语音服务器。国内网络访问不了 Google，识别立即报 `network` 错误，所以语音功能在国内等于完全不可用（不是个别情况）。
上游模型也帮不上忙：当前配置的 DeepSeek 没有语音识别接口。

本机检查结果（2026-11-07）：

- Windows 自带离线中文语音识别引擎 `MS-2052-80-DESK`（zh-CN）已安装，可以用 `System.Speech` 直接调用，**不联网、不花钱**。
- 用 Windows 自带的中文语音合成（Huihui）造了 7 句测试音频，离线识别结果：

| 原句 | 识别结果 | 耗时 |
|---|---|---|
| 线性无关到底是什么意思，能再举个例子吗 | 线性无关到底是什么意思能再举个例子吧 | 450ms |
| 还是不懂 | 还是不懂 | 88ms |
| 懂了 | 懂了 | 55ms |
| 不是 | 不是 | 28ms |
| 不确定 | 不确定 | 83ms |
| 这个公式里的特征值为什么要大于零 | 这个公式里的特征值为什么要大于里了 | 222ms |
| 为什么这里要取对数 | 为什么这里要去对数 | 123ms |

纯听写模式下「懂了」会被识别成「读了」；加上一组「快捷回复短语」语法后，短句全部识别正确。长句偶有同音错字，但 Call 3 的模型能读懂。

### 1.2 方案：浏览器只录音，本机代理识别

```
麦克风 ──getUserMedia──▶ 扩展（页面内录音 16kHz 单声道 + 本地静音检测）
        ──WAV(base64)──▶ 本地代理 POST /asr
                          ├─ 默认：Windows 离线识别（听写 + 快捷回复短语）
                          └─ 可选：config.json 里配置的云端识别（OpenAI 兼容 /audio/transcriptions），失败自动退回本机
        ◀── 文字 ──────── 自动作为追问发出（走原来的 Call 3 流式）
```

**扩展（`extension/content.js`）**

- 点麦克风开始录音；按钮变红并随音量跳动，输入框提示「正在听…说完停一下自动发送」。
- 静音检测：先测 0.3 秒环境噪音，阈值＝max(0.012, 噪音×3)；听到说话后**静音 0.7 秒**判定说完（沿用规格第 6 节的静音阈值）。
- 6 秒内没听到说话 → 提示「没听到声音」；单次最长 20 秒；录音中再点一次麦克风＝立即结束并发送。
- 识别结果 ≥2 个有效字、且不是纯语气词（嗯/啊/呃…）→ 自动发送；否则填进输入框让用户改。
- 错误分别提示：麦克风权限被拒 / 没有麦克风 / 代理是旧版本（没有 `/asr`，提示重启代理）/ 识别引擎不可用。
- 保留旧的浏览器识别作为可选项：设置页「语音识别方式」＝本机识别（默认）/ 浏览器自带（需要能访问 Google）。

**代理（`proxy/server.ps1`）**

- 新增 `POST /asr`：入参 `{ audio: "data:audio/wav;base64,…" }`，出参 `{ ok, text, engine, ms }`。
- 本机识别：启动时初始化一次 `SpeechRecognitionEngine(zh-CN)`，加载听写语法 + 快捷回复短语语法（懂了 / 还是不懂 / 展开讲讲 / 是 / 不是 / 不确定 …），之后每次请求复用。
- 可选云端识别：`config.json` 新增 `asr` 段：`engine`（`local` / `cloud` / `off`）、`baseUrl`、`apiKey`、`model`。云端失败自动退回本机。
- `/health` 和启动横幅显示「语音识别 可用（本机离线 zh-CN）」或不可用原因。
- 每次识别写一行日志 `type: "asr"`（引擎、音频秒数、耗时、字数、错误），不存音频。

**与规格的差异（写进规格第 10 节变更记录）**：规格第 6 节的「首个 partial ≥4 字就发起」依赖流式识别，本机识别没有 partial，改为「静音 0.7 秒 → 整句识别（短句 <100ms）→ 发送」。

### 1.3 验收

- [x] `/asr` 用合成的中文 WAV 测试，返回正确文字。
- [x] 模拟页里用「假麦克风」（把测试音频当麦克风输入）走完：录音 → 静音检测自动结束 → `/asr` → 自动发出追问 → Call 3 流式回答。
- [x] 拒绝麦克风权限 / 代理没开时有明确提示，不白屏。

## 二、抓不到字幕时的醒目指引

### 2.1 现状问题

v1.1 只在抽屉顶部用 12px 黄字写一句「本次没有抓到字幕」，而且**要等用户求助之后**才出现。用户不知道为什么没字幕、也不知道怎么开、开了以后还要做什么（字幕是播放时采集的，开了之后要倒回去重播一段才有上下文）。

### 2.2 先判断「为什么没字幕」

读 B 站播放器的字幕菜单（2026-11-07 在 B 站实际页面上核对过类名）：

| 状态 | 判断依据 | 给用户的话 |
|---|---|---|
| `off` 有字幕没打开 | 有 `.bpx-player-ctrl-subtitle-language-item`，但没有一个是 `bpx-state-active` | 这个视频有字幕，只是没打开 |
| `need_login` 要登录 | `.bpx-player-ctrl-subtitle-language-unlogin` 显示中 | B 站的 AI 字幕要登录后才能看 |
| `none` 暂无字幕 | 有字幕按钮，但没有任何语言 | 这个视频暂时没有字幕 |
| `no_button` 无字幕功能 | 播放器里没有 `.bpx-player-ctrl-subtitle` | 这个视频没有字幕 |
| `on` 已打开 | 有语言是 `bpx-state-active`，或最近 8 秒抓到过字幕 | （字幕开着，但这一段还没播过） |

### 2.3 三处指引，越来越醒目

1. **播放中主动提醒**（还没求助就提醒）：本视频累计播放 ≥20 秒，仍然一句字幕都没抓到（播放器字幕、画面硬字幕都没有）→ 播放器顶部弹出琥珀色提示条：「没检测到字幕，学习搭子的解释会不准」+ 原因 + 按钮【一键打开字幕】（仅 `off`）/【知道了】/【不再提示】。同一个标签页里每个视频只提醒一次，15 秒后自动收起；【不再提示】＝所有视频都不再主动提醒（设置页「抓不到字幕时主动提醒」可以改回来）。
2. **暂停按钮下方**：暂停时如果这一段（±30 秒）没有字幕，「我这里不懂」按钮下方多一行琥珀色小字「这段没抓到字幕，解释可能不准」。
3. **抽屉里的指引卡片**（替换原来的小黄字）：琥珀色边框 + 标题「没抓到这段的字幕」+ 原因 + 编号步骤 + 操作按钮：
   - 【一键打开字幕】：自动点开播放器字幕菜单里的中文字幕（优先人工 CC 中文，其次 AI 中文），1.5 秒内确认字幕出现；点不开就在播放器「字幕」按钮上画一个闪烁的圈，写「点这里打开字幕」。
   - 【倒回 30 秒重看】：关抽屉，倒回 30 秒继续播放；播到这里再暂停求助，就有前后文了。
   - 「字幕取自画面 / 读了画面文字 / 看了画面」等说明降为卡片底部一行小字。

每次提醒和点击写日志 `type: "client_event", event: "sub_guide"`（位置、字幕状态、动作、结果），用来看指引有没有用。

### 2.4 验收

- [x] 模拟页把字幕状态切到「没开 / 要登录 / 无字幕 / 无按钮」，四种文案都对。
- [x] 「没开」状态下点【一键打开字幕】，模拟播放器的字幕被打开，卡片变成「已打开 ✓」。
- [x] 播放 20 秒无字幕时出现主动提醒；【不再提示】后同一视频不再出现。
- [x] 有字幕的正常视频不出现任何提醒。

## 三、历史节点：记录、一句话说明、选择节点回溯

### 3.1 什么是一个「节点」

用户每打开一次学习搭子（暂停点「我这里不懂」或按 1）并拿到解释，就生成一个节点：

| 字段 | 说明 |
|---|---|
| `id` / `videoId` / `subject` | 节点编号、视频、课程标题 |
| `t` / `timestamp` | 视频里的位置（秒 / mm:ss） |
| `createdAt` / `updatedAt` | 打开时间 / 最后一次追问时间 |
| `call2` | 当时的三段解释（原文 + 字数等） |
| `transcript` / `screenText` / `originalConcept` / `route` | 继续追问需要的上下文（字幕节选限 2000 字） |
| `turns` | 追问记录：问、答、模式、路由、输入方式 |
| `summary` / `summarySource` | 一句话说明（`ai` 模型生成 / `rule` 规则生成） |

存在 `chrome.storage.local` 的 `hist:<视频ID>`，每个视频最多 50 个节点（超出删最旧的），总占用超过 8MB 时删最久没看的视频。**只存在本机浏览器里**，由扩展后台统一读写（多个标签页同时写也不会互相覆盖）。

### 3.2 一句话说明

- **立即**：节点一生成就有规则说明，例如「卡在『只有零系数才能组合出零向量』· 追问 2 次 · 已懂」。
- **会话结束时**（关抽屉 / 继续播放后再求助 / 切到别的节点 / 离开页面），节点有变化就由扩展后台调用代理新接口 `POST /summarize`（**Call 4**，提示词 `prompts/call4_summary.md`，temperature 0.3，非流式），生成 ≤30 字的一句话说明，写回节点。放在后台做，所以关掉页面也不会丢。
- 失败或没配 Key 时保留规则说明，不影响使用。设置页可以关掉「用 AI 生成一句话说明」。
- **补生成**（实施时补充）：会话没正常结束的节点（关标签页时后台被回收、当时代理没开）下次打开同一视频时由后台补上，每次最多补 3 个、只补 1 分钟内没改过的。
- 日志 `type: "call4"`。

### 3.3 回溯

- 抽屉标题栏新增【历史】按钮（带本视频节点数）。点开是本视频的**节点时间线**（最新在上）：`[03:25]` 视频位置 + 一句话说明 + 「11-07 14:32 · 追问 2 轮」。当前打开的节点标「当前」。
- **选择节点 = 回溯**：
  1. 视频跳到该节点的位置并暂停（画面回到当时提问的那一帧附近）；
  2. 抽屉还原当时的三段解释和全部追问记录，顶部标出「回溯 · 11-07 14:32 的记录」；
  3. 可以**接着追问**：沿用当时的字幕上下文、路由和前几轮记录，新的追问追加到这个节点上，说明随之更新；
  4. 【返回】回到节点列表；在时间线上点别的节点可以继续跳。
- 设置页新增「学习历史」：按视频列出所有节点和一句话说明，点节点打开对应视频并直接回溯到该节点（设置页先在 `chrome.storage` 记一条 `pendingRestore`，再打开带 `t=` 的视频链接；视频页加载后 2 分钟内读到它就回溯，读完即删）；可清空。
- 日志：`history_open`（打开时间线）、`history_restore`（选择了哪个节点）；`close` 事件增加 `node_id`、`restored`。

### 3.4 验收

- [x] 求助 2 次（不同位置），时间线上出现 2 个节点，各有一句话说明（规则说明立即出现，AI 说明会话结束后替换）。
- [x] 点旧节点：视频跳回该位置，抽屉还原当时的解释和追问；接着追问后节点的追问数 +1。
- [x] 刷新页面后历史还在；设置页能看到并能跳转回溯、能清空。

## 五、不做的事

- 不改 Call 1 / 2 / 3 的提示词原文（只新增 Call 4）。
- 不上传录音、不存录音；历史只存在本机浏览器。
- 不在 B 站进度条上画节点标记（B 站播放器控制条会自动隐藏，叠加层容易错位，留到以后）。
