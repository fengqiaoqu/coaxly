## 一、UI 重新设计（Anthropic 审美）

### 1.1 设计原则

Anthropic（含 Claude 产品）的视觉语言可以概括为：**暖色中性底 + 陶土橙一处点睛 + 衬线体读正文 + 细线代替阴影 + 大量留白 + 克制的动效**。v1.1/v1.2 用的是冷灰底 + 青绿强调色 + 无衬线，信息密、按钮多是彩色填充，和这个方向正好相反。

落到本项目的取舍：

1. **颜色**：底色从冷灰白换成暖象牙白；唯一的品牌强调色是陶土橙（clay），只用在「发送」、时间戳、当前项、重点标记这几处；其余按钮一律中性（细线描边或深墨色实心）。琥珀色警示改成更柔和的牛皮纸色（kraft / manilla）。
2. **字体**：解释正文、追问回答、标题、历史/重点的说明用**衬线体**（读起来像一页笔记，而不是一条通知）；按钮、标签、元信息用无衬线。不加载任何网络字体（B 站页面里、国内网络都不可靠），只用系统字体栈：拉丁字母和数字走 Georgia，中文按顺序回落到 思源宋体（Noto Serif SC / Source Han Serif SC）→ 华文宋体 → 宋体。
3. **层次**：去掉彩色标签底块，改成「小号无衬线标签 + 陶土色小圆点」；分隔用 1px 细线；阴影只保留极浅的一层用于浮在视频上的元素。
4. **对话**：用户追问是浅色气泡，学习搭子的回答**不加气泡**、直接衬线排版（和 Claude 的回答呈现方式一致）。
5. **不用 Anthropic / Claude 的标志和名称**：只借鉴审美，不做品牌仿冒；标识仍是「学习搭子」文字 + 一个陶土色圆点。

## 二、课程重点：读取字幕上下文，判定重点节点并标注

### 2.1 目标

看课时用户最想知道的是「这节课哪几处必须弄懂」。v1.3 读取字幕，让模型判断**哪些时间点是重点**（核心定义、关键结论、方法关键步、老师明确强调、易错点），然后：

- 在 B 站**进度条上打标记**（看一眼就知道重点在哪）；
- 抽屉里有**重点列表**，点一条就跳过去播放；
- 播放**经过重点时**轻轻提示一下；
- 暂停求助时，如果附近有重点，提示「附近重点：……」。

### 2.2 字幕从哪来：两条路

| 来源 | 什么时候用 | 能标注的范围 |
|---|---|---|
| **完整字幕**（优先） | 视频是 BV/av 号，且 B 站给了字幕文件（人工 CC 字幕，或登录后的 AI 字幕） | **全片**：刚打开视频就能提前标出后面的重点 |
| **已播放字幕**（兜底） | 没有完整字幕（没登录看不了 AI 字幕、番剧、硬字幕视频、请求失败） | 只能标**已经播过的部分**：v1.1 起就有的字幕采集器（播放器字幕 + 画面硬字幕识别）边播边攒，攒够一段就分析一段 |

**读取完整字幕**（在内容脚本里做，和 B 站播放器自己取字幕走同一组接口，带用户自己的登录态）：

1. `GET api.bilibili.com/x/web-interface/view?bvid=…`（或 `aid=`）→ 按分 P 取 `cid`；
2. `GET api.bilibili.com/x/player/v2?bvid=…&cid=…`（失败再试 `/x/player/wbi/v2`）→ `data.subtitle.subtitles`；
3. 选字幕：人工中文 → AI 中文 → 其他中文 → 任意一条；
4. 下载 `subtitle_url` 的 JSON，`body[] = { from, to, content }` → 按时间排好的字幕表。

2026-11-08 在 B 站页面上核对过：这两个接口从 `www.bilibili.com` 页面里带 cookie 请求能正常返回；没登录时 AI 字幕返回 `need_login_subtitle: true` 且列表为空。

**校验（防止拿错字幕）**：B 站这个接口历史上出现过返回别的视频字幕的情况，所以拿到后要校验，不通过就丢弃、改走「已播放字幕」：

- 字幕至少 10 行；
- 最后一行的结束时间不超过视频时长 + 30 秒，且不早于视频时长的一半；
- 播放过程中播放器上实际出现过的字幕（≥3 句）里，至少有一句能在完整字幕的 ±10 秒内找到相似句（2-gram 相似度 ≥0.5）。事后发现不匹配 → 丢弃完整字幕和据此标出的重点。
- 为了不在「串台」的字幕上白花一次调用：完整字幕还没对上号、本视频播放不到 60 秒、播放器上**正在显示字幕**（已抓到 1–2 句）时，先等攒够 3 句、比对通过再分析；视频暂停时（例如一打开就点开重点面板）、或播放器根本没开字幕时不等。

**顺带的改进**：有了完整字幕后，「我这里不懂」的 ±30 秒字幕窗口在已播放字幕不够时（例如刚打开就拖到中间暂停）用完整字幕补上；播放 20 秒没抓到字幕的提醒条在有完整字幕时也不再弹出。

### 2.3 判定重点：Call 5（`/keypoints`）

**分段**：

- 完整字幕：按约 5 分钟一段切（在字幕行之间切，最后不足 90 秒的并进上一段）。先分析当前播放位置所在的段，再往后，最多提前分析到当前位置后 30 分钟，往前补已经看过的段；一次只跑一段，跑完歇 1.5 秒。长合集不会一口气把几十段全跑完。
- 已播放字幕：上次分析到的位置之后，攒够 150 秒视频时长且 ≥200 字（或攒到 1200 字），就分析这一段；视频播完、或在重点面板点【分析已播放部分】时立即分析剩下的。
- 本视频累计播放满 10 秒才开始（只是点开看一眼的视频不花调用）；打开重点面板也会立即开始。

**代理新接口 `POST /keypoints`**：

- 入参：`video_id`、`subject`、`span_from` / `span_to`（秒）、`duration`、`lines: [{ t, text }]`、`known`（本视频已标过的重点标题，避免重复）、`source`（`track` / `live`）。
- 提示词：新文件 `prompts/call5_keypoints.md`（占位符 `{{subject}} {{span}} {{duration}} {{known}} {{max_points}} {{transcript}}`），要求只输出 JSON：
  `{"points":[{"t":"mm:ss","title":"≤14 字","note":"≤36 字","kind":"定义|结论|方法|强调|易错","level":1|2}]}`。
  「什么算重点」写死在提示词里：核心概念第一次定义、关键结论/定理/公式、方法关键一步、老师明确强调、常见误区；开场白、寒暄、复述上节课、闲聊、过渡句不算；宁缺毋滥，每段最多 `max_points` 个（`max(1, min(6, ⌈段长秒数 / 100⌉))`，5 分钟一段就是 3 个），`level 2`（本段最核心）最多 1 个。
- 调用参数：`config.model`，temperature 0.2，max_tokens 600，非流式，JSON 模式；上游不支持 JSON 模式就去掉 `response_format` 重试一次（和 Call 1 同一套兜底）。
- 代理校验：`t` 必须落在本段范围内（±5 秒），并对齐到 20 秒内最近的一行字幕时间；标题 / 说明去 Markdown、截断到 16 / 40 字；`kind` 不在列表里记为「强调」；15 秒内重复的合并（留 level 高的）；和 `known` 标题相同的丢掉；`level 2` 每 5 分钟最多 1 个，多的降成 1（模型偶尔会把两条都标成核心）；超过上限的按 level、先后截断。
- **规则兜底**（没配 Key、上游失败、返回的不是合法 JSON）：按字幕里的提示词匹配——「容易犯 / 容易错 / 容易混 / 误区 / 混淆 / 千万别 / 千万不要 / 别搞错 / 常见错误 / 易错」→ 易错，「重点 / 关键 / 核心 / 记住 / 考试 / 常考 / 必考 / 注意」→ 强调，「叫做 / 称为 / 称作 / 定义」→ 定义，「定理 / 结论 / 公式 / 总结 / 也就是说 / 本质上」→ 结论（按这个顺序，先命中的算）；紧挨着的几句（15 秒内，如「这是重点」「大家记住」）只算一个，每 5 分钟最多 2 个，标 `src: "rule"`，面板上显示「关键词」。
- 日志：每次一行 `type: "call5"`（段范围、行数、来源、标出几个、是否兜底、耗时）。

### 2.4 存储

`chrome.storage.local` 的 `kp:<视频ID>`：

| 字段 | 说明 |
|---|---|
| `points[]` | `{ id, t, timestamp, title, note, kind, level, src: 'ai'/'rule', source: 'track'/'live' }`，按时间排序 |
| `spans[]` | 已经分析过的时间段 `[from, to]`，用来判断哪段还没跑 |
| `trackLan` / `source` | 依据的字幕（完整字幕的语言 / 已播放字幕） |
| `updatedAt` | 超过 150 个视频时删最久没更新的 |

只存在本机浏览器；同一个视频再次打开直接读缓存，不重复调用。设置页可以清空。

### 2.5 标注在哪

1. **进度条标记**：在 B 站播放器的进度条（`.bpx-player-progress`，鼠标移上去时显示）和底部常驻细进度条（`.bpx-player-shadow-progress-area`，控制条收起时显示）里各插一层标记：陶土色细竖条，核心重点是小菱形。标记在 B 站自己的进度条元素里面，所以控制条自动隐藏 / 显示、全屏、窗口缩放都跟着走，不会错位（v1.2 不做进度条标记的顾虑就是浮在外面会错位）。标记不拦截点击（点进度条照样是 B 站自己的跳转）；鼠标在进度条上移到标记附近时，上方浮出「◆ 重点 · 标题」小卡片。B 站把这层标记重绘掉时，每秒检查一次补回来。
2. **抽屉「重点」面板**：标题栏新增【重点 N】，和【历史】并列。列表按时间排：时间戳 + 标题（衬线）+ 一句话说明（和标题重复时不显示，规则兜底常见）+ 类型（定义 / 结论 / 方法 / 强调 / 易错）；核心重点标「核心」；你在附近求助过的标「求助过」；当前播放位置所在的那条高亮。点一条＝关掉抽屉、跳到重点前 2 秒开始播放。面板底部写清依据和进度（「依据完整字幕 · 已分析到 15:00 / 48:12」或「依据已播放的字幕 · 继续播放会接着标注」），没登录、没配 Key、代理没开时写原因。
3. **播放经过重点时的提示**：播放正常经过一个重点（不是拖动跳过去的）时，视频左上角浮出一条小卡片「◆ 重点 · 线性无关的定义」，5 秒后收起，点它打开重点面板。设置页可关。
4. **暂停时**：如果前 45 秒 ~ 后 15 秒内有重点，「我这里不懂」下方多一个胶囊「附近重点：……」，点开重点面板。

### 2.6 设置与日志

- 设置页新增「课程重点」：自动标注课程重点（默认开）/ 读取完整字幕（默认开，需要登录 B 站才有 AI 字幕）/ 播放经过重点时提示（默认开）/ 清空重点标注。
- 日志 `client_event`：`kp_track`（完整字幕：ok / none / need_login / mismatch / unsupported / error，语言、行数）、`kp_jump`（从哪里跳的：panel / cue）、`kp_cue`（shown / click）、`kp_open`（打开重点面板）。

### 2.7 验收

- [x] 模拟页（完整字幕模式）：播放 10 秒后进度条上出现全片重点标记，抽屉【重点】列出标题 / 说明 / 类型，点一条跳到该位置播放。
- [x] 模拟页（没有完整字幕）：边播边标，播过的段落出现重点；【分析已播放部分】立即分析。
