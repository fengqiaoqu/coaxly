## 第 6 节 语音链路：从「流式 partial」改为「本机整句识别」

| 约束 | 原规格 | v1.2 |
|---|---|---|
| 识别引擎 | `webkitSpeechRecognition`，`interimResults=true`，首个 partial ≥4 字即发起 Call 3 | **默认改为本机识别**：扩展用 `getUserMedia` 录 16kHz 单声道 → `POST /asr` → Windows 离线 zh-CN 识别（听写语法 + 快捷回复短语语法）→ 自动作为追问发出。原方案保留为设置页可选项「浏览器自带」 |
| 为什么改 | — | Chrome 的识别要把音频发到 Google，国内网络访问不了，立即报 `network` 错误：**语音功能在国内整体不可用**（v1.2 的 Bug 1） |
| 判定说完（VAD） | 静音阈值不要设长 | 先测 0.3 秒环境噪音，阈值＝max(0.012, 噪音×3)；说话后**静音 0.7 秒**判定说完；6 秒没听到声音提示「没听到」；单次最长 20 秒；录音中再点一次麦克风＝立即结束 |
| 首字延迟 | partial 提前发起，省 200–400ms | 没有 partial；但本机识别快：短句 <100ms、7 秒长句约 0.35 秒，静音 0.7 秒 + 识别 + Call 3 首字与原方案同一量级 |
| 太短 / 语气词 | 不足 4 字不发 | 少于 2 个有效字（单字「是 / 对 / 不 / 好 / 行 / 嗯」除外）或只有「嗯 / 啊 / 呃」→ 不自动发送，填进输入框 |
| 可选云端 | — | `config.json` 的 `asr.engine = "cloud"`：走 OpenAI 兼容 `/audio/transcriptions`（`asr.model` 必填），失败自动退回本机；`"off"` 关闭 |
| 隐私 | — | 录音只发到本机代理，识别完即丢，不落盘 |

## 第 7 节 降级与失败处理矩阵（新增行）

| 故障 | 处理 | 用户看到 |
|---|---|---|
| 字幕抓不到 / 长度 < 10 | 仍走 `call2_degraded.md`（不变） | 原来的 12px 小黄字换成琥珀色**指引卡片**：按播放器状态区分「没打开 / 要登录 / 没有字幕」，带【一键打开字幕】（仅「没打开」）和【倒回 30 秒重看】 |
| 播放 20 秒还没抓到任何字幕 | 扩展主动提醒，每个视频每个标签页一次，15 秒自动收起 | 播放器上方琥珀色提示条：一键打开字幕 / 知道了 / 不再提示 |
| 暂停时这一段没有字幕 | — | 「我这里不懂」下方多一行「这段没抓到字幕，解释可能不准」 |
| 一键打开字幕失败 | 在播放器「字幕」按钮上画闪烁圈 | 「点这里打开字幕」 |
| 麦克风权限被拒 / 没有麦克风 / 代理是旧版（无 `/asr`）/ 识别引擎不可用 / 没听到声音 | 按错误类型分别提示，不白屏 | 输入框上方提示，可以直接打字 |
| Call 4 失败 / 没配 Key / 会话没正常结束 | 保留规则生成的一句话说明；下次打开该视频时后台补生成（最多 3 个） | 历史时间线照常显示 |

## 第 8 节 数据留存（新增记录类型和字段）

| `type` | 来源 | 主要字段 | 用途 |
|---|---|---|---|
| `asr` | 代理 | `engine`、`engine_used`、`audio_sec`、`text`、`chars`、`ok`、`error`、`total_ms` | 识别准确率和耗时；**不存音频** |
| `call4` | 代理 | `node_id`、`timestamp`、`turn_count`、`summary`、`chars`、`total_ms`、`error` | 一句话说明的质量 |
| `client_event` · `sub_guide` | 扩展 | `where`（toast 提示条 / drawer 指引卡片）、`action`（shown / open / rewind / dismiss / never / timeout）、`state`（on / off / need_login / none / no_button）、`result`（打开字幕：ok 或失败原因）、`lan`、`from` / `to`（倒回） | 字幕指引有没有用：提醒后多少人真的打开了字幕 |
| `client_event` · `voice` | 扩展 | `engine`、`result`（sent / filled / empty / no_speech / denied / no_mic / mic_error / asr_error / browser_error）、`chars`、`audio_ms` | 语音追问的成功率 |
| `client_event` · `history_open` | 扩展 | `where`（ask 暂停按钮旁 / drawer 抽屉标题栏）、`nodes` | 历史时间线的使用频率 |
| `client_event` · `history_restore` | 扩展 | `where`（drawer 时间线 / options 设置页）、`node_id`、`node_t`、`node_age_ms`、`turns`、`summary_source` | 回溯了多久以前的节点 |
| `close`（新增字段） | 扩展 | `node_id`、`restored` | 回溯后的会话是否继续追问 |

`call4` 的 `session_id` 与触发它的那次会话一致；后台补生成的那几条没有 `session_id`。

## 第 9 节 参数总表（新增一行）

| 调用 | 模型 | temperature | max_tokens | 流式 | JSON 模式 |
|---|---|---|---|---|---|
| Call 4 一句话说明（`prompts/call4_summary.md`） | `config.model` | 0.3 | 80 | 否 | 否 |

代理对 Call 4 的输出只取第一行，去掉「说明：」之类的前缀、整句外面的一对引号和句末句号，超过 40 字截断。会话结束时（关抽屉 / 再次求助 / 切换节点 / 离开页面）由扩展后台调用，不占用前台等待时间。

## 第 10 节 已知取舍与变更记录（v1.2 新增行）

| 项 | 原始规格 | 本项目决策 | 理由 |
|---|---|---|---|
| 语音识别 | 浏览器流式 STT + 首个 partial | **本机离线整句识别**（浏览器识别降为可选） | 国内连不上 Google 语音服务；Windows 自带 zh-CN 引擎离线、免费、够快 |
| 无字幕提示 | 抽屉内一行文字 | **三级醒目指引**（主动提示条 → 暂停提示 → 抽屉指引卡片）+ 一键打开字幕 | 用户不知道为什么没字幕、怎么开、开了还要倒回去重播 |
| 学习历史 | 只有 past3 给 Call 2 换角度 | **历史节点**：每次求助一个节点，带一句话说明（规则即时 + Call 4 异步），可选择节点回溯并接着追问 | v1.2 建议 2；只存本机浏览器 |
| 进度条节点标记 | — | 本期不做 | B 站控制条会自动隐藏，叠加层容易错位 |
